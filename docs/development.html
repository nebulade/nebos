Development

Edit, reload, watch the boot line.

A normal iteration does not reflash anything. The board receives a new kernel and rootfs over serial or UDP, parks its APs, jumps into the new image and prints the same version line on COM1. A runtime command-pack update can skip even the kernel reload.

Toolchain

NebOS builds with a normal GNU toolchain for 32-bit x86, plus mtools for FAT images and QEMU for testing. The UEFI loader is the only 64-bit component and needs the mingw cross compiler.

  • Compiler. gcc with 32-bit multilib, as, ld, objcopy.
  • Kernel flags. -m32 -march=i586 -ffreestanding -fno-pie -nostdlib -fno-stack-protector -mno-sse -mno-sse2 -mno-mmx -O2.
  • Warnings. The build uses -Wall -Wextra; a new warning is a bug, not noise.
  • User commands. Linked at 0x40000000 with ucmd.ld, stripped, and packed as bin/<name>.
  • UEFI. x86_64-w64-mingw32-gcc builds BOOTX64.EFI; make all does not require it.
  • Images. mtools builds root.img and the ESP.

Serial reload

COM1 runs at 115200 8N1. The WM idle loop watches the receive ring for the KXE2 magic and auto-spawns the reload, so a plain make dev is enough. The manual kexec command is a fallback that waits for the same image. 

[magic "KXE2"][entry u32][kernel_size u32][pack_size u32]
[kernel][rootfs gzip][checksum u8]
  • Full reload. make dev stages kernel and rootfs in one page-allocated buffer, copies the kernel to 0x7E00 and publishes the pack range in boot info.
  • Kernel only. make kernel-dev sends pack_size == 0; the new kernel keeps the running rootfs.
  • Pack only. make cmds-dev uses KXNP and ramfs_replace(), without a kernel jump.
  • Monitor. Run make monitor in a second terminal; each reload prints NebOS v0.2.0 booted on COM1.

The serial receive drops the BKL while it waits for bytes, so the WM and the other CPU's syscalls stay responsive during a reload.

Network reload

For boards without a serial port, the same reload runs over UDP port 19288 with the KXN2 magic. The host tool sends the kernel and rootfs as one stop-and-wait stream; the board acknowledges every datagram with the next expected offset and verifies a 32-bit checksum before jumping. 

make net-dev                    # kernel + rootfs to 192.168.178.240
make net-dev BOARD_IP=192.168.178.42
make kernel-net-dev             # kernel only; keep the rootfs
make net-cmds                   # replace /ramfs only

The board must be idle at a shell prompt. The WM loop answers ARP/ICMP, detects the KXN2/KXNP header and pauses the auto-detect while a packet-level command owns the NIC or a transfer is in progress. Datagrams are at most 1400 bytes.

The board address comes from DHCP when a server is present; use make net-dev BOARD_IP=<leased-address>, or pin an address with netip on the board.

Runtime command pack

make cmds-dev sends the raw cmds.pack with the KXNP magic. The receiver validates the pack before the swap, so a truncated transfer leaves the running commands untouched. A good pack is installed by ramfs_replace() and the old heap copy is freed.

  • Existing processes are unaffected. They already loaded their ELF.
  • The next spawn sees the new files.
  • RAM only. A cold boot uses the flashed rootfs; reflash after changing the bundle.

Tests

  • USB regression. make test-usb runs QMP cursor and keyboard tests against UHCI, OHCI, EHCI and xHCI, including hotplug.
  • Image library. make test-images decodes a corpus of PNG/JPEG/GIF/BMP/TGA/PNM/ICO/PAM files and checks blits; the ASan variant catches memory errors.
  • Crypto. make test-crypto runs host vectors for the freestanding crypto code.
  • UEFI. make test-uefi boots the dual image under OVMF headless and greps the serial log for the boot line.
  • Compositor stats. The ring-3 WM overwrites /share/wmstats every two seconds with frames, total and worst compositing time in milliseconds, and the pixels drawn in the interval. Read it in a terminal or fetch it over WebDAV to measure a target.

Debugging

  • Serial log. make monitor shows the boot trace and printf-style driver output. The NebOS v… booted line is written before the framebuffer is ready.
  • Network console. make netmon listens to UDP 19290 for serial and terminal output; netconsole host <ip> narrows the target.
  • dbg. The ring-0 serial monitor accepts r addr len, w addr b0 …, i port, o port val, h and q.
  • Panic. A ring-0 fault dumps vector, error code, registers, CRs, EIP bytes and stack candidates to the LFB and COM1. Resolve addresses with nm kernel.elf / addr2line -e kernel.elf.
  • Profiling. gfxbench times fill/copy/cell/canvas/flush; top, sched, sensors, powerinfo, power and lspci/lsusb expose live state.
  • Memory. peek addr len hex-dumps identity-mapped memory (MMIO too); poke addr val writes one dword and prints the read-back.

Conventions & gotchas

  • Freestanding C. No libc, no malloc, no printf. Use io_putstr, io_putchar and io_puthex.
  • Fresh memory is not zeroed. Clear structures whose fields are read before being written. QEMU starts RAM clear and hides the bug.
  • Keep the memory map in sync. Hardcoded addresses appear in assembly, C headers and linker scripts; changing one without the others breaks boot or loading.
  • Ring-3 data segments. An IRET to ring 3 nulls DS/ES/FS/GS whose DPL is below CPL 3. Kernel stubs must restore selector 0x23 with IRQ_RETURN_DS. QEMU does not model this; only real hardware fails.
  • Paging is flat. Physical equals virtual everywhere; there is no process isolation.
  • The BKL is not preemptible. A BKL holder can be in the middle of kernel structures; block points drop it, and bkl_pause() is for long waits.
  • Kernel size wall. _end must stay below 0x90000; the legacy staging gap also constrains the loaded image and the compressed pack.
